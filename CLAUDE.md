# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Status

The project is officially unmaintained (see the README notice, which stays); changes are dependency refreshes, not feature work.

## Build

- Requires JDK 25 (`java.version` in the root POM): `j25 && mvn clean install`
- There are no JUnit tests. `MainCreateXSLTFromSchematron` in `en16931-xml-validator/src/test` is a manual utility whose relative paths point outside this repo.
- Verify validator changes by running the fat jar (`en16931-xml-validator/target/*-jar-with-dependencies.jar`) with `-xml <file>` plus `-xsd`, `-sch`, `-xslt` or `-pure <file>` (optionally `-svrl <file>`). Compiling is not enough: missing runtime dependencies only show up here.

## Generated code - do not edit

- `en16931-edifact-to-xml/src/main/java/com/altova/**` and `com/mapforce/**` are Altova MapForce output (excluded from the license check). The only hand-written class is `MainEdifactToXml`. It was generated by MapForce 2017sp2 (at GEFEG); the `.mfd` mapping source is not in any known repository, so this code cannot be regenerated.
- `en16931-edifact-xml` has no hand-written Java; classes are generated by `jaxb-maven-plugin` + `ph-jaxb-plugin` from `src/main/resources/schemas/INVOIC_D14B_ISO20625.xsd` and `src/main/jaxb/binding.xjb` (Jakarta namespace). Change those inputs, not `target/`.
- The XSD root element `List` generates a class named `List`, which forces `java.util.List` to be fully qualified - a known trigger for invalid JSpecify annotations from `ph-jaxb-plugin`.

## Dependency gotchas

- `SchematronResourceSCH` lives in `ph-schematron-isosch`, not `ph-schematron-xslt`.
- The validator needs `com.sun.xml.bind:jaxb-impl` at runtime for SVRL handling (SCH/XSLT modes); without it the CLI reports the Schematron as "malformed".
- Java packages are `eu.cen.en16931.*` although the groupId is `com.helger.en16931`.
